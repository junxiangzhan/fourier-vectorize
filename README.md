# fourier-vectorize

把一張圖畫成傅立葉級數，輸出可以直接用瀏覽器開啟的 SVG，也能從級數放大到任意倍率。

做法：雙邊濾波後，把 Lab 三個通道各切成數階（預設 32 + 16 + 16），每階的次像素輪廓各擬合一條傅立葉級數，再用梯度下降修正。SVG 裡每個通道是一張版，由 SVG 濾鏡轉回 RGB，輪廓以三次貝茲曲線和直線表示。有透明度的圖多一張 alpha 版，在 SVG 裡是蓋在畫面上的遮罩。

## 建置

需要 Rust。

```bash
cargo build --release
```

## 使用

```bash
fourier-vectorize fit photo.jpg --out output
fourier-vectorize render output/photo_refined_m0.2.fvc --svg --out output
```

`fit` 輸出 `<圖名>_<方法>_m0.2.fvc`（壓縮過的係數，`render` 只需要它）與 `<圖名>_<方法>.json`（尺寸、各階數值、壓縮後畫出來的 ΔE、SSIM）。`render` 讀回係數，畫成 SVG 和／或 BMP。

`fit` 讀 PNG、JPEG 和未壓縮的 24-bit BMP，依檔案內容判斷格式，與副檔名無關。會依 EXIF 方向轉正。內嵌的色彩描述檔會被忽略，不做色彩管理。解碼後超過 512 MB 的 PNG 或 JPEG 會被拒絕。

輸出檔名只取圖名、不含副檔名，所以輸出到同一個資料夾時，`photo.png` 和 `photo.jpg` 會互相覆蓋。

### 透明度

有透明或半透明像素的 PNG，輸出的 SVG 也是透明的。BMP 沒有透明度，所以 BMP 和 JSON 裡的 ΔE、SSIM 都以疊在白底上的結果為準。

檔案裡存在全透明像素底下的顏色看不見，不會影響結果：這些像素會改用周圍可見的顏色延伸。反鋸齒的邊只用一條輪廓，只有緩慢的淡出才會多用幾階，上限是 `--levels` 的第四個數字（預設 16）。

從一幅 493×640 的畫做出的三張圖（預設設定）：

| alpha | `.fvc` | SVG | 第四個數字改成 8 |
|---|---|---|---|
| 橢圓挖空，邊緣一像素 | 105 kB | 696 kB | 完全相同，只用到 2 階 |
| 大範圍淡出 | 136 kB | 963 kB | SVG 小約 4%，ΔE 從 1.29 變 2.05 |
| 沿著畫裡的形狀挖空 | 182 kB | 1268 kB | SVG 小約 12%，ΔE 幾乎不變 |

大範圍淡出用 16 階時看得出一圈圈的色帶。這張圖改成 32 階，SVG 大約 8%，ΔE 降到 1.03。

透明的畫面只在 Edge 上驗證過；SVG 同時依賴遮罩和濾鏡，其他軟體可能不支援。

| `fit` 選項 | 作用 | 預設 |
|---|---|---|
| `--factor N` | 以 N×N 區塊平均縮小 | 長邊縮到不超過 2000 px 的最小倍數 |
| `--levels L,a,b[,alpha]` | 各通道的階數（2..64）；第四個數字只影響有透明度的圖 | `32,16,16,16` |
| `--method dft\|refined\|descent` | DFT、DFT 加梯度下降、只從圓開始梯度下降 | `refined` |
| `--csv` | 輸出 `<圖名>_<方法>_coefficients.csv`（每條輪廓的每個 c_k），不輸出 `.fvc`；檔案大很多，之後可用 `pack` 以不同 `--movement` 壓縮 | 輸出 `.fvc` |

| `render` 選項 | 作用 | 預設 |
|---|---|---|
| `--scale N` | 從級數放大 N 倍（1..16），不經點陣重取樣 | 1 |
| `--svg`、`--bmp` | 輸出哪種檔案；BMP 把透明度疊在白底上 | 兩種都輸出 |

## 檔案大小的取捨

這些參數由使用者決定，程式不會自動選擇。

| 選項 | 作用 | 預設 | 是否失真 |
|---|---|---|---|
| `fit --keep 比例` | 刪減係數到指定比例（0 到 1 之間），再以梯度下降修正；係數檔只含留下的係數 | 不刪 | 是 |
| `fit --prune largest\|lowpass` | 依 \|c_k\| 大小，或只留低頻。低通在低比例時留下的會多於指定比例，k = −1、0、1 一律保留 | `largest` | |
| `fit --rounds N` | 分 N 次、每次按相同比率刪到目標；1 為一次刪完 | 1 | |
| `fit --prune-steps N` | 梯度下降總步數：一半分給各輪，一半留給最後的係數集 | 400 | |
| `render --lines` | SVG 輪廓只用直線，不用曲線；放大時會看到折角 | 曲線 | 是 |
| `render --tolerance PX` | 簡化 SVG 輪廓時可移動的距離（輸出像素）；0 只刪完全共線的點 | 0.1 | 是 |
| `render --decimals N` | SVG 座標小數位數（0..4） | 1 | 是 |
| `fit --movement PX`、`pack --movement PX` | 量化係數，讓每條輪廓移動約這個 RMS 距離（像素） | 0.2 | 是 |

SVG 一律使用相對座標，這一步本身不損失資訊。設定會記錄在檔名裡（如 `photo_refined_keep0.17_largest_r8_s400_m0.2.fvc`、`photo_refined_m0.2_lines_t0.5_d0.svg`），不同設定不會互相覆蓋。BMP 直接由級數填色，不受 `--lines`、`--tolerance` 與 `--decimals` 影響。

在兩幅畫上的實驗（各 4 個比例）：保留約 11% 以上時，多輪略優（如 8 輪、400 步保留約 17%）；約 7% 以下則一次刪的色差較小。選法則因畫而異。樣本很少，只能當起點參考。

### 曲線與直線

SVG 預設用一條三次貝茲曲線代替一段連續的點，直線比較省的地方仍用直線，切線取自級數的導數，所以曲線之間接得平滑。同樣的 `--tolerance` 下，在兩幅畫上量到（未刪減係數）：

| 輸出 | 960×1247 的畫 | 1762×799 的畫 |
|---|---|---|
| 1 倍，`--lines` | 2.81 MB，0.6 秒 | 5.08 MB，0.8 秒 |
| 1 倍，曲線 | 2.56 MB，1.1 秒 | 4.77 MB，1.6 秒 |
| 8 倍，`--lines` | 10.37 MB | 19.26 MB |
| 8 倍，曲線 | 7.25 MB，7.6 秒 | 12.98 MB，10.6 秒 |

1 倍的曲線檔放大 8 倍檢視時，看不出直線檔那樣的折角，只是擬合較慢。它會把容差用得比較滿，所以同容差下與原曲線的差距略大：若把畫質調到相同，未刪減係數的曲線檔在 1 倍時反而比直線大約 10%，經低通刪減的係數則小約 10–25%（原型在一幅畫上的量測）。如果只以原尺寸顯示，又想要最少的座標，先調高 `--tolerance`，效果遠大於換用哪一種線段。

## 壓縮係數

`.fvc` 把係數量化成整數，再用 LZMA2 壓縮。這個檔案本身就含畫布尺寸和基底階數，`render` 只需要它就能畫，不用 JSON。瀏覽器不能直接開 `.fvc`，要顯示時用 `render` 輸出 SVG。

`fit` 預設就輸出它。想比較不同的 `--movement`，不必重新擬合：先用 `fit --csv` 留下 CSV，再用 `pack` 壓縮。

```bash
fourier-vectorize fit photo.jpg --csv --out output
fourier-vectorize pack output/photo_refined_coefficients.csv --out output --movement 0.4
```

CSV 也能直接給 `render`，但要和同名的 JSON 放在一起。

在兩幅畫上量到的大小與平均 ΔE（未刪減係數，預設階數）：

| `--movement` | 960×1247 的畫 | 1762×799 的畫 |
|---|---|---|
| 不壓縮（CSV） | 36.9 MB，1.994 | 54.1 MB，2.278 |
| 0.1 | 0.50 MB，2.002 | 0.86 MB，2.284 |
| 0.2 | 0.36 MB，2.020 | 0.64 MB，2.303 |
| 0.4 | 0.26 MB，2.066 | 0.47 MB，2.357 |

搭配 `fit --keep` 還能再縮小，但色差會增加得更快。
